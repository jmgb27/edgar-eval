# Judge calibration

Every faithfulness number this repository publishes comes from an LLM judge.
An uncalibrated judge produces figures that look like evidence without being
evidence, so the judge is measured against known labels before it is allowed
to score anything. This file is generated by `scripts/calibrate_judge.py`.

- **Judge**: `claude-haiku-4-5`, temperature 0
- **Prompt**: `c3643f3e117c6b2a` (see `src/edgar_eval/eval/judge.py`)
- **Set**: `eval/labels/judge_calibration.jsonl`, 50 triples, balanced 50/50
- **Runtime**: 67s

## How the labels are known

Each triple is a matched pair built from the curated gold set: the verified
reference answer with its supporting passage (GROUNDED), and the same answer
with exactly one fact corrupted against the same passage (UNGROUNDED). The
label is therefore certain by construction rather than by anyone's judgement,
and the pair isolates the thing that matters — noticing that a figure changed.

## What this does and does not establish

It establishes that the judge reliably notices when a figure in an answer
is not in the passages, and does not raise false alarms on answers that are
sound. That is the specific failure this project cares about most, and it is
now measured rather than assumed.

It does **not** establish that the judge is good at faithfulness in general.
The corruptions here are unambiguous by construction — a leading digit is
changed, so `$394,328` becomes `$994,328` — which is an easier discrimination
than the subtle cases real generation produces: a figure from the right table
but the wrong column, a correct number attributed to the wrong year, a claim
that overstates what a hedged sentence actually said. A score of 1.000 on this
set should be read as *the instrument is not broken*, not as *the instrument is
perfect*.

Two limits worth stating plainly:

- **n = 50.** At this size a single flipped judgement moves TPR or TNR
  by four points, so small differences between runs are not meaningful.
- **The set is synthetic.** Every triple is built from verified gold answers
  rather than from model output, which is what makes the labels certain — and
  also what makes them unrepresentative of how a real answer goes wrong.

Harder cases belong in this set as they are found. The honest next step is
adding corruptions that are plausible rather than obvious, and re-measuring.
